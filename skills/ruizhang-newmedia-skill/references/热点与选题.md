# 村上春墅 · 热点获取与借势选题

> 用户问“今天有什么热点/热榜/热搜”“帮我找选题”时，先跑脚本，再按本文件筛选。
> 热点只是**选题输入**，不是事实来源；涉及政策、事故、数据时必须回到官方发布核对。

---

## 一、抓取脚本

```bash
python scripts/fetch_hot.py --limit 5
python scripts/fetch_hot.py --platform weibo,douyin --limit 10
python scripts/fetch_hot.py --out 热点.md
```

覆盖平台与可靠性：

| 平台 | 来源 | 可靠性 | 说明 |
|---|---|---|---|
| 百度热搜 | top.baidu.com 直连 | 高 | 解析页面 s-data |
| 微博热搜 | 60s 公共接口 | 中高 | 第三方聚合，可能限流 |
| 抖音热榜 | 60s 公共接口 | 中高 | 第三方聚合，可能限流 |
| 微信视频号 | tophub 今日视频榜 | 中 | 直连易 403，走 Jina 可能限流 |
| 微信公众号 | tophub 24h 热文榜 | 中 | 同上 |
| 小红书 | 无稳定公开源 | 低 | 默认失败；可用 `XHS_HOT_URL` 自建接口，或手动提供 |

**小红书替代方案**（按优先级）：
1. 用户提供已登录的小红书截图/链接，人工提炼
2. 配置 `XHS_HOT_URL` 指向自建或付费接口（返回 `[{title,hot,url}]` 或 `{data:[...]}`）
3. 使用 RedFox / TikHub / SocialDataX 等带 Key 的服务，后续可再接

## 二、筛选原则（先判断能不能用）

对每条热点问四个问题：

1. **相关性**：和「乡村 / 建房 / 家装 / 宅基地 / 家庭 / 适老 / 工程」有没有自然连接？
2. **可借势**：能不能从工程、标准、居住、家庭角度切入，而不是硬蹭？
3. **风险**：是否涉及时政敏感、灾难事故、医疗断言、明星八卦、地域对立、未成年人？
4. **时效**：是否还在上升期？是否已被大量账号消耗？

**优先级**：政策/行业 > 居住生活 > 家庭情感 > 工程科技 > 社会话题 > 娱乐八卦（基本放弃）。

## 三、可借势的方向（示例）

| 热点类型 | 可用角度 | 不要做 |
|---|---|---|
| 国家工程/大国重器 | 工程标准、施工装备、质量管控 | 政治评论、宏大叙事硬拔高 |
| 城市更新/楼市政策 | 回乡建房、宅基地、翻建审批 | 预测房价、承诺升值 |
| 健康/适老 | 适老化设计、无障碍动线、防滑防潮 | 医疗诊断、疗效暗示 |
| 家庭/亲情 | 回乡建房、给父母留一间房 | 煽情过度、道德绑架 |
| 天气/台风/梅雨 | 防水防潮、抗台风工艺 | 消费灾害、制造恐慌 |
| 返乡/就业 | 返乡建房、乡村创业、加盟赛道 | 夸大收益、保证回本 |

## 四、输出模板（热点选题）

```markdown
# 今日热点借势选题｜{日期}

## 热点概览
- 平台/条目/热度：
- 来源与抓取时间：

## 可用选题（3–5 个）
### 选题 1｜{标题}
- 借势热点：
- 关联点：{为什么和村上春墅有关}
- 目标受众：C 端业主 / B 端加盟商 / 泛流量
- 建议平台与账号：
- 钩子类型：
- 风险提示：

## 不建议使用的热点
- {条目}：{原因}
```

## 五、合规红线

- 不评论时政、不预测政策、不解读领导人讲话。
- 不消费灾难、事故、伤亡；不拿悲剧做营销。
- 不传谣；政策、补贴、审批口径以政府官方发布为准。
- 不做医疗断言，不暗示疗效。
- 不蹭未成年人、隐私、地域对立、性别对立。
- 热点数据只作为选题参考，不当作事实引用。

## 六、失败处理

- 某个平台失败：在输出里明确写“未获取 + 原因”，不要编造。
- 小红书失败：提示用户手动提供，或询问是否配置 API。
- 所有平台都失败：改用用户手动提供的热点，或直接做常青选题（避坑/工艺/案例）。
