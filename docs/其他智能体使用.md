# 同事用其他 AI 工具怎么接

> 这个 skill 的本质是 **Markdown 文件 + 一个 Python 脚本**，不绑定 Claude Code。
> 但不同工具的支持程度不同，先看你的工具属于哪一类。

## 一、先判断工具类型

| 类型 | 代表工具 | 能否自动加载 | 推荐接法 |
|---|---|---|---|
| 支持 Agent Skills 的编程智能体 | Codex、Cursor、Gemini CLI、WorkBuddy、Hermes | 部分可以 | 用 `AGENTS.md` / `GEMINI.md` 做入口 |
| Claude.ai | Claude 网页版/桌面版 | 可以 | 上传 skill 或建 Project |
| 普通聊天机器人 | 豆包、Kimi、文心、通义 | 不能 | 知识库 + 系统提示词 |
| 智能体/知识库平台 | Coze、Dify | 不能自动读文件 | 知识库 + 工作流 + 提示词 |

**核心区别**：只有支持 skill 机制的 agent 才会“自动触发”。普通聊天机器人需要你把资料喂给它。

## 二、Codex / Cursor / Gemini CLI

仓库根目录已经放了：

- `AGENTS.md`（Codex、Cursor 等会读）
- `GEMINI.md`（Gemini CLI 会读）
- `.cursor/rules/ruizhang-newmedia.mdc`（Cursor 规则）

### 使用步骤

1. 把仓库拉到本地，或用工具打开这个仓库。
2. 直接说：“用村上春墅 skill 写一条抖音防水视频，30 秒。”
3. Agent 会读取 `skills/ruizhang-newmedia-skill/SKILL.md` 和 `references/`。

### 如果它不自动读

在对话里明确说：

```text
请先读取 skills/ruizhang-newmedia-skill/SKILL.md，
再按它的指引读取 references/ 下的相关文件。
```

### 注意

- 不同版本对 `AGENTS.md` / `SKILL.md` 的支持不一样；以 `AGENTS.md` 为入口最稳。
- 如果工具不能执行 Python，热点脚本用不了，需要手动提供热点。

## 三、Claude.ai

### 方式 1：上传 Skill（如果套餐支持）

1. 打开 Claude 设置，找到 **Capabilities / Skills**
2. 上传 `ruizhang-newmedia-skill.zip`
3. 新开对话，说“用村上春墅 skill……”

> 不同套餐/版本的入口可能不同；找不到就用方式 2。

### 方式 2：Project + 知识库

1. 新建一个 Project
2. 上传这些文件到 Project 知识库：
   - `references/品牌知识.md`
   - `references/内容方法论.md`
   - `references/平台与账号.md`
   - `references/合规红线.md`
   - `references/热点与选题.md`
   - `references/事实核验与检索.md`
3. 把 `docs/通用提示词.md` 的内容设为 Project 指令
4. 新开对话使用

## 四、豆包 / Kimi / 文心 / 通义 / Coze / Dify

这些工具不能自动读取 skill 文件夹，需要两步：

### 第 1 步：建知识库

按优先级上传：

1. `品牌知识.md`（必须）
2. `合规红线.md`（必须）
3. `事实核验与检索.md`（必须）
4. `内容方法论.md`
5. `平台与账号.md`
6. `热点与选题.md`
7. `文案样例库.md`（可选）

### 第 2 步：设置系统提示词

复制 `docs/通用提示词.md` 全文，粘贴到：

- 豆包/Kimi：自定义指令 / 智能体设定
- Coze：人设与回复逻辑
- Dify：系统提示词

### 第 3 步：使用

```text
我是新媒体销售，帮我写一条余姚同城视频，
主题“农村翻建审批的坑”，30秒，目标收集本地线索。
```

## 五、通用提示词（节选）

完整版见 `docs/通用提示词.md`。核心要求：

```text
你是村上春墅的新媒体运营助手。

1. 先确认平台、账号类型、主题、时长、目标；没说就按“抖音+企业品牌号+30-45秒”。
2. 输出：选题说明、标题、文案、话题、口播、分镜、SRT、封面、合规自检。
3. 品牌数字只能来自知识库；没有就说“资料里没有”，不要编造。
4. 需要事实性内容但知识库没有时，主动检索官方来源，标注链接和日期；
   检索不到就问用户，不要猜。
5. 发布前检查：电话/门牌/抽烟/小孩/喝酒、风水迷信、贬低同行、
   收益承诺、审批必过、工期承诺。
```

## 六、必须提前说明的限制

1. **不会自动触发**：普通聊天机器人不会自己判断该用这个 skill，每次要说明品牌和任务。
2. **上下文有限**：不要把整个 `references/` 全贴进去，优先用知识库检索，或只贴相关文件。
3. **热点脚本跑不了**：`fetch_hot.py` 需要 Python 和联网执行；没有就手动喂热点。
4. **图片读不了**：没有文件/视觉能力的工具无法读取 `assets/` 里的品牌手册图片。
5. **合规仍需人工复核**：任何工具的输出都不能直接发布。
6. **事实核验**：涉及政策、补贴、审批、造价、工期、竞品时，必须回到官方来源核对。

## 七、一张图看懂

```text
支持 skill 的 agent → 读 SKILL.md + references → 自动执行
Claude.ai          → 上传 skill / Project 知识库 → 手动触发
普通聊天机器人      → 上传知识库 + 系统提示词 → 手动提问
```

不管用哪种，**“不编造、缺信息就查、查不到就问”** 这条规则都不能省。
